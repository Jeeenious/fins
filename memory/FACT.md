- **主线程调度循环（装配点带锁事务，非成员函数）**：main() 主函数装配完 worker 后跑装配点调度循环（持 `graph_g.mtx`），每轮先集中更新回调槽（`if (graph_g.wcet_updater) graph_g.wcet_updater(graph_g); if (graph_g.priority_updater) graph_g.priority_updater(graph_g);`），再集中做超周期启停判断：`stopped.load()` → `is_hp_done()` 图静止 → ① 有 `pending.load()` → **`pipeline_g.cache.commit()` + `parse_pipeline(read())` + check_topology + `expand_hp(pipeline_g, library_g)`**（try-catch FINS_LOG_ERROR 兜底）→ `pending = false` + `cv.notify_all()`；② 有 `hyper_period>0` → `rollover_hp()` → `cv.notify_all()`；否则 `cv.wait_for(1ms)`（notify 唤醒 / 超时兜底）。**worker 纯拉取执行**：on_execute 回调（装配点写带锁单步事务，持 `graph_g.mtx`）：`stopped.load()` 检查 → `grab_ready_workload()` 锁内拉取（置 Running，返回图内顶点 Workload* 含 id/job，**不回绕**）→ 锁外 `w->job()` 执行 → 回锁直做完成事件（w->state = Finished + `cv.notify_all()`）→ 无可拉 `cv.wait()`。std::mutex 不可重入：持锁勿再 lock()。test_assembly 结构：TEST 1/2/3 抽独立测试线程，main 跑装配点调度循环阻塞，测试线程末尾 `graph_g.stopped = true; graph_g.cv.notify_all();` → 主线程循环返回 → main pool.stop() + join + 清理；TEST 1/2 轮询经 `graph_g.dag.size()`/`hyper_start_ms` 观察（持 mtx）。
- **收包 = 装配点两条指令（磁盘 JSON 双缓冲）**：RPC /update handler 内 `pipeline_g.cache.write() = j`（存**原始配置 JSON**到缓冲份）+ **`graph_g.pending = true; graph_g.cv.notify_all();`**（公开成员直写）；**不解析，HTTP 恒 200**）；建图由 **main 主线程调度循环**检测 pending + 图静止后调用：`pipeline_g.cache.commit()`（**双缓存 = `Pipeline::cache` 成员** `util::DoubleBuff<nlohmann::json>`，write() 返回 T&/read() 返回 const T&/active() 返回 T&，**无 operator\***，勿写 `*pipeline_buf_g.write()`——**pipeline_buf_g 全局不存在**）→ `pipeline_g.parse_pipeline(cache.read())`（**第一级 json 格式审查 + 拆封**，违反抛异常拒绝）→ `pipeline_g.check_topology()`（**第二级图结构审查**：① 单写者 ② 源周期必填）→ `graph_g.expand_hp(pipeline_g, library_g)`。**无 script/DoubleBuff/version 成员**（配置不保留原始 JSON——注意 cache 是 2026-08-27 新增的 JSON 双缓冲成员，区别于被删的 script 双缓冲）。parse_pipeline 拆封：顶层 array/{nodes:[...]}/单节点（null→空表）；NodeInfo 构造器逐节点格式校验：name/version/id 必填 string、parameters 数组元素须 object 且含 value（位置式取值表 config_cache，名字丢弃）、inputs/outputs 数组元素须 string、wcet/deadline/period/cap number、priority integer、loop 拆 loop_timer/loop_step 两 map。
- **pipeline_g = struct Pipeline（独立全局，带壳）**：成员 `cache`（util::DoubleBuff<nlohmann::json>，配置 JSON 双缓冲）+ `nodes`（vector<Pipeline::NodeInfo>）+ `parse_pipeline(config)`（**无返回**，拆封顶层 + 逐个触发 NodeInfo 构造）+ `check_topology()`（**第二级图结构审查**）+ **private `wr_mtx_` + public `wr_lock()`**（RPC 并发写 cache 的串行锁访问，装配点 lock_guard 持用）。**JSON 解析/校验归 Pipeline**：图侧/运行时不再接触 JSON 类型判断，只消费解析好的 NodeInfo。
- **Pipeline::NodeInfo（解析态，Pipeline 结构体内嵌套，纯数据不参与执行）**：id/name/version；inputs/outputs **端口名数组**（input_ports/output_ports，顺序 = AlgoFunc 参数顺序）；config_cache（有序 value 表）；loop 拆两个 map<string,float>：loop_timer/loop_step；period/wcet/deadline/priority/cap 数值（cap 默认 10，config 顶层 "cap" 可配）。**命名**：解析态必须写全 `Pipeline::NodeInfo`（图顶点是命名空间级 `Workload`，勿混淆）。
- **AlgoBase 纯执行接口（无字段）**：`struct AlgoBase { virtual ~AlgoBase()=default; virtual void initial(){}; virtual void execute(const std::vector<Message>& inputs, std::vector<Message>& outputs)=0; virtual void configure(const std::string& key, const nlohmann::json& value)=0; }`。execute 收"按端口序排列"的输入/输出数组。**AlgoFunc 参数布局契约（configs-first）**：用户函数参数必须"配置段+输入段+输出段"排列。详见 algo_func.hpp 头注释。
- **graph_g = struct PrecedenceGraph（独立全局，唯一带壳运行时；全局变量名 graph_g，勿写 d_graph_g）**：`dag` 成员 = DirectedAcyclicGraph<Workload, Message>、边 = Message 槽（共享帧）；+ `hyper_period` + `hyper_start_ms` + `exec_us_hist_`（map<string, deque<double>> 节点 id → 最近 execute 耗时 us）+ `exec_hist_cap{100}` + `record_exec(id, us)`。**它既是数据流图也是调度依据**。`expand_hp(const Pipeline&, const Library&)`（图域唯一入口，输入显式入参）= 清空 + **单函数一步建图**（①结构分析→②超周期→③拓扑序→④实例化→⑤支配周期/实例数→⑥建顶点→⑦建边→⑧填 job 闭包）；loop 滑动窗口容量是**成员 `mesg_hist_cap`**。
- **无相位重构**：顶点 vtx 现拼 id+":"+k。**就绪条件 = 前序边来源全部 Finished**（唯一前序条件）。**abs_deadline 按序排** = hyper_start_ms + (k+1)·deadline。**绑定 = 时段内最新已完成帧整数式**：pk = ((k+1)·Np-1)/Nc（向下取整，恒有边）。**单写者约束**：同 stream 多 producer 时 check_topology 抛 std::invalid_argument。**offset 保留为 DelayAlgo 的 sleep_for 时长**，非 JSON 配置。**支配周期**：未配置 period 的后级继承前级最终周期（多前级继承最短周期前级）。**虚拟源 hist:{stream}:{k} 整体删除、延迟顶点不建**。
- **Loop 显式端口补充定义**：节点 config 顶层 `"loop"` = `{"step": {端口: 迭代步}}` / `{"timer": {端口: 观测周期}}`。loop 端口在拓扑序/支配继承/绑定边中全部跳过（无自环边），反馈走运行时**滑动窗口数据槽 `message_hist_[端口]`**（容量 = producer 节点 `NodeInfo.cap`，默认 10；回绕不清、满丢最旧、expand 重建保留）。job 闭包聚合**恒长** `std::vector<Message>`（w 帧），窗口未满开头补空 Message 0 值占位（frame=nullptr，算法须判断 .frame 跳过/当 0，勿 sub——sub 空帧抛异常）。
- **顶点四态状态机 + 无类型标记**：`enum class State { Pending, Ready, Running, Finished }`，删 Kind 枚举。**图顶点 = 命名空间级 `Workload`**：`struct Workload { State state{Pending}; float period{0}; float deadline{1}; float wcet{1}; float abs_deadline{0}; std::function<void()> job; }`——扁平字段，**含 `std::string id`（expand ⑥ 建顶点时填 vtx，grab_ready_workload 返回的 Workload* 含 id，装配点直做完成事件用）**。job 非空 = 正常 job 实例顶点。**job 闭包只执行不碰 state**：Running 由 grab_ready_workload 拉取时置、Finished 由装配点回锁直做置（回绕重置 Pending）。
- **内置工具算法 = delay/ringbuf 二件套（StagingAlgo 删除）**：`algo_utility.hpp` 只留 DelayAlgo（透传 + offset 阻塞 sleep_for）+ RingBufferAlgo（depth 滚动 + back 选窗；depth=1 即 latest-value）。用户拍板"staging 没必要，ringbuf 长度设 1 就好"。
- **调度闭环 + 就绪判定（2026-08-27 落地，晚再改锁 + 状态升公开成员 + 完成事件装配点直做）**：就绪判定框架内置（前序全 Finished + Pending → Ready，完成事件由装配点回锁直做推进（置 Finished + cv.notify_all()），源节点靠拉取即投）；**两回调槽（装配点注入，组件不含业务）**：`set_wcet_updater(cb)` + `set_priority_updater(cb)`（槽 = 全局 inline，**main 主线程调度循环每轮持 mtx 集中更新**）。**priority 只存 Workload（grab_ready_workload 读源），不写回 Computation**。停止：`graph_g.stopped = true + cv.notify_all()` → 主线程循环返回 + on_execute 回调返回 false → worker 退出。
- **library_g（唯一算法定位数据源，磁盘无 so_contexts_g_）**：`struct Library { util::TBBMap<std::shared_ptr<Plugin>> so_ctx; }; inline Library library_g;`。loader 只做库机制；装配点经 on_library_add/on_library_modify/on_library_delete（载荷 (so_path, shared_ptr<Plugin> ctx)）→ SET/ERASE。类型名 Plugin。回调名 on_library_*。**expand_hp 不隐式读本表——调用方显式传 library（library_g）入参**。
- **组件接口统一 init + start(线程数) + 公开幂等 stop()**：RPCListener / PluginLoader 均拆成"init 定配置 + start 唯一参数 = 线程数"两段，构造函数不再预建线程池，两者 start 都含 joinable() 幂等检查，调用点 init 后 start(4)。**RPC on_library_* 的落地目录是路由参数 plugin_dir（非 set_work_dir）**。**RPCListener/PluginLoader 公开幂等 stop()（2026-08-27 补全，析构复用）**：RPCListener::stop() = `server_->stop(); if (listening_.joinable()) listening_.join();`；PluginLoader::stop() = `guard_->stop(); if (watching_.joinable()) watching_.join();`；析构改 `~X() { stop(); }`。回收顺序 = 先 `graph_g.stopped=true; graph_g.cv.notify_all();` → ThreadPool::stop() → RPCListener::stop() → PluginLoader::stop()。
- **thread_pool.hpp 已解耦 g_state + bool 回调**：不 include g_state，不定义 Job；**on_execute 收 bool 回调（成员 `std::function<bool()> cb_`）**，worker 循环 `while (!stop_.load()) { if (!cb_) break; if (!cb_()) break; }`，回调内自行"取任务 + 执行"（典型 = 装配点写带锁单步事务：持 graph_g.mtx → stopped.load() → grab_ready_workload（返回 Workload* 含 id/job）→ 锁外 job() → 回锁直做完成事件（w->state = Finished + notify）→ cv.wait）。**停止约定**：`stop()` 置 stop_ + join 回收 worker，不置调度停止位——装配点须先 `graph_g.stopped = true; graph_g.cv.notify_all();` 再 pool.stop()；只调 pool.stop() 不先置位唤醒会 join 死锁。测试收尾均 graph_g.stopped = true + cv.notify_all() + pool.stop()。
- **Plugin 生命周期**：`explicit Plugin(const std::string &path)` 构造器=装载（dlopen + dlsym 解析 C 符号 + 枚举填 loaded_keys；失败抛异常）；`~Plugin()`=dlclose；`take_keys()`=move 走并清空 loaded_keys 返回。**删 load_so / unload_so**。loader make_shared<Plugin>(path) 构造装载。

## 反馈/经验
- 组件方法先想有没有实际消费者：create_algo/create_job/build_job 只有 expand 一个消费者 → 全内联删掉。
