## 核心分层（2026-08 确立，2026-08-31 就绪集优先级队列 + 键函数定稿）
- 调度状态/锁 = PrecedenceGraph 公开成员：`mtx`/`cv`/`stopped`/`pending`（装配点直接读写，无访问器薄封装）。只留核心算法函数（无锁原语，调用方持 mtx）：`expand_hp(p,l)`/`grab_ready_workload()`/`grab_delay_workload()`/`is_hp_done()`/`is_hp_empty()`/`rollover_hp()`/`trigger_workload_ready(id)`/`update_abs_deadline()`/`is_workload_ready()`。保留 2 个回调槽（命名空间级 inline 变量，装配点直接赋值注入）：`wcet_updater`/`priority_updater`。
- **回调槽更新时机（2026-08-27 起主线程集中 → 2026-08-31 用户拍板分治 → 键函数化）**：`wcet_updater` 新签名 `std::function<double(std::deque<double>)>`（输入节点执行历史 deque → 输出估计 wcet；client.cpp 旧调用已删，装配逻辑待定）；`priority_updater` **迁入 `grab_ready_workload` 调度决策点**（主线程循环不再调用）——勿加回主线程 priority_updater 调用。
- **priority_updater = 优先级键函数（2026-08-31 定稿）**：签名 `std::function<int(PrecedenceGraph&, const Workload&)>`（命名空间级 inline，装配点直接赋值注入；可读 *this 全图状态如 hyper_start_ms/核心负载）。**优先级唯一来源——grab 前对就绪顶点逐个现算覆盖入队占位 0**。**优先级不可预设原则（用户拍板）**：`Workload.priority` 字段与 `NodeInfo.priority` 配置项均已删除（开发者无法预设，只能经键函数拿到）；未注入回调 → prio 恒 0 → 就绪堆退化为纯 FIFO。
- **就绪集 = 懒最大堆（2026-08-31 定稿，封装进 util::LazyMaxHeap）**：`ready_` = `util::LazyMaxHeap<ReadyItem, ReadyItemLess>`（`struct ReadyItem { std::string id; size_t seq; int prio; }`，私有嵌套；`ReadyItemLess` 私有嵌套仿函数 = prio 高者顶、相等 seq 小者先出）。`util::LazyMaxHeap<T, Compare>`（utils/form.hpp，DoubleBuff 之后）：push 只入队不做 push_heap（懒）、rebuild() 一次性 make_heap O(n)、pop_max() pop_heap+pop_back O(log n) 取顶、data() 底层批量快照、clear/empty/size。`grab_ready_workload` 流程 = `ready_.empty()` 早退 → `if (priority_updater)` 对 `ready_.data()` 逐项 `item.prio = priority_updater(*this, dag.vertex(item.id))` 现算（唯一来源；未注入跳过）→ `ready_.rebuild()` → `ready_.pop_max()` → `mutate_vertex` 取图内 Workload\*。入队 = 内联 `ready_.push({id, ready_seq_++, 0})`（ready_push 辅助函数已删），prio 占位 0 grab 前现算填真值。`expand_hp`/`rollover_hp` 清 ready_ 时同步 `ready_seq_ = 0`。**性能诚实预期：无渐进收益**（键函数现算 O(n) + make_heap O(n) ≈ 原线性扫描）；收益在结构工整（真正 priority queue 抽象、pop O(n) erase → O(log n)、比较逻辑集中一处）与就绪顺序确定性。
- **就绪入队时机（2026-08-31 用户确认）**：入队（内联 ready_.push + seq 分配）留在**完成事件**（trigger_workload_ready 里 pred_left 减到 0 时），seq=就绪时刻 → FIFO 精确；**grab 前只做 rebuild 重排 prio，不重新判定/入队**（grab 一次只取一个无法给其余就绪顶点补定序；grab 前判定需 O(V) 扫描违背增量设计）。勿改为 grab 前统一入队。
- 主线程调度循环（装配点带锁事务，非成员函数）：main() 每轮持 `graph_g.mtx` 先集中 `update_abs_deadline()` + `wcet_updater(graph_g)`，再超周期启停判断：`stopped.load()` → `is_hp_done()` 图静止 → ① `pending.load()` → commit+parse_pipeline+check_topology+expand_hp（try-catch FINS_LOG_ERROR 兜底）→ pending=false+notify；② `hyper_period>0` → `rollover_hp()` → notify；否则 `cv.wait_for(1ms)`。worker 纯拉取执行：on_execute 回调（带锁单步事务）：`stopped.load()` 检查 → `grab_ready_workload()` 锁内拉取（返回图内 Workload\* 含 id/job，置 Running 语义 = 拉走即隐式运行）→ 锁外 `w->job()` 执行 → 回锁 `trigger_workload_ready(w->id)`（置 done + 传播 pred_left + 入 ready）+ notify → 无可拉 `cv.wait()`。timer 线程与 worker 对称：`grab_delay_workload()`（tp 时间点游标）→ 锁外 sleep job → 回锁 trigger_workload_ready + notify。
- 收包 = 装配点两条指令（磁盘 JSON 双缓冲）：RPC /update handler 内 `pipeline_g.cache.write() = j` + `graph_g.pending = true; graph_g.cv.notify_all();`（不解析，HTTP 恒 200）；建图由 main 主线程调度循环检测 pending + 图静止后调用。无 script/DoubleBuff/version 成员（注意 cache 是 2026-08-27 新增的 JSON 双缓冲成员，区别于被删的 script 双缓冲）。
- pipeline_g = struct Pipeline（独立全局，带壳）：`cache`（util::DoubleBuff<nlohmann::json>）+ `nodes`（vector<Pipeline::NodeInfo>）+ `parse_pipeline(config)`（无返回）+ `check_topology()`（第二级图结构审查）+ private `wr_mtx_` + public `wr_lock()`。JSON 解析/校验归 Pipeline，图侧/运行时只消费解析好的 NodeInfo。
- Pipeline::NodeInfo（解析态，Pipeline 结构体内嵌套，纯数据）：id/name/version；inputs/outputs 端口名数组；config_cache（有序 value 表）；loop 拆两个 map<string,float>：loop_timer/loop_step；period/wcet/deadline/cap 数值（cap 默认 10；**priority 已删——优先级不预设**）。命名：解析态写全 `Pipeline::NodeInfo`（图顶点是命名空间级 `Workload`）。
- AlgoBase 纯执行接口（无字段）：`virtual void initial(){}; virtual void execute(const std::vector<Message>& inputs, std::vector<Message>& outputs)=0; virtual void configure(const std::string& key, const nlohmann::json& value)=0;`。AlgoFunc 参数布局契约（configs-first）：用户函数参数必须"配置段+输入段+输出段"排列。
- graph_g = struct PrecedenceGraph（独立全局，唯一带壳运行时）：`dag` 成员 = DirectedAcyclicGraph<Workload, Message>、边 = Message 槽（共享帧）；+ `hyper_period` + `hyper_start_ms` + `exec_us_hist_`（map<string, deque<double>>）+ `exec_hist_cap{100}` + `record_exec(id, us)`。`expand_hp(const Pipeline&, const Library&)`（图域唯一入口）= 清空 + 单函数 9 步建图（①端口索引→②超周期→③拓扑序→④实例化→⑤支配周期/实例数→⑥建顶点→⑦建边→⑦.5时间链 pin_sync→⑧填 job 闭包 bind_job→⑨就绪初始化）。loop 滑动窗口容量是成员 `mesg_hist_cap`。
- **tp 顶点 wcet 理论值（2026-08-31 定稿）**：tp 顶点不 record_exec（计时只在 bind_job 普通节点闭包），wcet_updater（deque→wcet 新签名）对 tp 无输入 → wcet 只能建图期理论写死。pin_sync 建 tp 顶点时 `v.wcet = off - prev_off`（相邻同步点间隔：worker 及时串行释放下每个 tp 恰好睡满自己那一段；tp:0=0 立即释放，总和 = 最后同步点偏移）。wcet 字段全仓库无运行时消费者（仅建图期填充元数据，等将来 EDF/可调度性消费）。
- **tp 时间点游标化（2026-08-28 定稿）**：`pin_sync` 按 offset 升序填全量 `tp_order_`（vector），`grab_delay_workload` 用游标 `tp_released_` O(1) 取下一个，无全图扫描；rollover 重放同一批 tp（tp_order_ 不清、游标归零）。
- **就绪增量状态（2026-08-31 升级）**：私有 `pred_left_`（剩余前序数）/`in_degree_`（入度基准）/`done_`（已完成集合）/`ready_`（util::LazyMaxHeap<ReadyItem, ReadyItemLess>）/`ready_seq_`（入队序号）/`tp_order_`+`tp_released_`。入队 = 内联 `ready_.push({id, ready_seq_++, 0})`（prio 占位 0，grab 前键函数现算填真值；ready_push 辅助已删）。`build_pred()`（⑨a 入度基准，private 建图辅助）：两趟填 in_degree_/pred_left_ 基准（初始值 = 入度）。`seed_ready()`（⑨b 初始就绪，须在 build_pred 之后）：无前序依赖（pred_left==0）且非 tp 门顶点内联入队（无 tp 门顶点兜底）。`trigger_workload_ready(id)`（完成事件）：done_ 插入（幂等）→ 对每个后继递减 pred_left_ 减到 0 且非 tp 者内联入队。
- 无相位重构：顶点现拼 id+":"+k。就绪条件 = 前序边来源全部 Finished。abs_deadline 按序排 = hyper_start_ms + (k+1)·deadline。绑定 = 时段内最新已完成帧整数式：pk = ((k+1)·Np-1)/Nc。单写者约束：同 stream 多 producer 时 check_topology 抛 std::invalid_argument。offset 保留为 DelayAlgo 的 sleep_for 时长，非 JSON 配置。支配周期：未配置 period 的后级继承前级最终周期。虚拟源 hist:{stream}:{k} 整体删除、延迟顶点不建。
- Loop 显式端口补充定义：节点 config 顶层 `"loop"` = `{"step": {端口: 迭代步}}` / `{"timer": {端口: 观测周期}}`。loop 端口在拓扑序/支配继承/绑定边中全部跳过，反馈走运行时滑动窗口数据槽 `message_hist_[端口]`（容量 = producer 节点 NodeInfo.cap，默认 10；回绕不清、满丢最旧、expand 重建保留）。job 闭包聚合恒长 `std::vector<Message>`（w 帧），窗口未满开头补空 Message 0 值占位（frame=nullptr，算法须判断 .frame 跳过/当 0，勿 sub——sub 空帧抛异常）。
- 图顶点 = 命名空间级 `Workload`（扁平字段，无生命周期状态——就绪/完成由 PrecedenceGraph 侧增量状态 pred_left_/done_/ready_ 判定）：`struct Workload { std::string id; std::string name; size_t k; double period; double deadline; double ddl; double wcet; std::function<void()> job; }`——**priority 字段已删（优先级不可预设，排序键唯一来源 = priority_updater 键函数 grab 前现算）**。job 闭包只执行不碰 state。
- 内置工具算法 = delay/ringbuf 二件套：`algo_utility.hpp` 只留 DelayAlgo（透传 + offset 阻塞 sleep_for）+ RingBufferAlgo（depth 滚动 + back 选窗；depth=1 即 latest-value）。
- 组件接口统一 init + start(线程数) + 公开幂等 stop()：RPCListener / PluginLoader / HardwareMonitor / ThreadPool 均拆成两段。thread_pool.hpp 已解耦 g_state + bool 回调（on_execute 收 bool 回调，worker 循环 `while (!stop_) { if (!cb_) break; if (!cb_()) break; }`）。回收顺序 = 先 `graph_g.stopped=true; graph_g.cv.notify_all();` → ThreadPool::stop() → RPCListener::stop() → PluginLoader::stop() → HardwareMonitor::stop()。
- Plugin 生命周期：`explicit Plugin(const std::string &path)` 构造器=装载（dlopen + dlsym 解析 C 符号 + 枚举填 loaded_keys；失败抛异常）；`~Plugin()`=dlclose；`take_keys()`=move 走并清空 loaded_keys 返回。删 load_so / unload_so。

## 反馈/经验
- 组件方法先想有没有实际消费者；调度状态/锁升公开成员 + 删薄封装（用户拍板"绝大多数没有必要封装成函数的形式"）。全局无裸调度状态、无访问器薄封装。勿加回 `*_g` 全局调度状态、勿加回访问器包装、勿加回 run_one()/scheduler_run()/pop_ready()/自锁包装、勿加回 on_job_done（完成事件装配点回锁直做）。
- grab_ready_workload 返回图内顶点 Workload\*（含 id/job，拉取即隐式 Running），装配点锁外 w->job() 执行 + 回锁 trigger_workload_ready(id)。勿退回返回 Job/pair/Workload 拷贝（拷贝改不到图内顶点会死锁）、勿把状态变更塞回 job 闭包。
- 5 核心函数重命名定稿：expand_hp / grab_ready_workload / is_hp_done / rollover_hp / trigger_workload_ready。勿改回旧名（含 set_workload_done / on_job_done）。
- GraphSpec 方案被否 + expand 合并单函数；expand 输入显式入参（const Pipeline&, const Library&）；JSON 解析归 Pipeline + parse_pipeline 命名；config 删除 + offset 去 JSON 化；顶点"标记状态而非类型"；支配周期原则；绑定整数式；Loop 必须显式定义；StagingAlgo 删除；struct Pipeline 带壳定稿。勿再改。
- **TBB spin_rw_mutex 不可重入**：持 const_accessor 期间对同一 map 写会单线程自旋死锁，须作用域释放。
- 图顶点命名 Workload（用户拍板）。执行耗时统计：`graph_g.exec_us_hist_` + `exec_hist_cap{100}` + `record_exec(id, us)`；record_exec 的 cap 读取用 `exec_hist_cap.count(id) ? at(id) : 100` 缺省兜底（勿 operator[]→0 致空 deque pop_front UB）。Loop 历史槽改滑动窗口：单一 `hist_`。hist 容量改 NodeInfo.cap + mesg_hist_cap 成员化；record_mesg 同样 count/at 缺省 100 防空 deque UB。
- **调度闭环事件流**：撤销事件队列改条件变量；scheduler_g 删除、就绪判定框架内置；主线程调度循环集中做超周期启停判断；调度状态全局收敛 → 升公开成员。勿再加回事件队列、勿加回全局调度状态。
- 锁 = PrecedenceGraph 公开成员 mtx（std::mutex 不可重入，持锁勿再 lock()）；测试并发观察读持 mtx 直读 dag。
- **DoubleBuff<T>（form.hpp）**：write() 返回 T&、read() 返回 const T&、active() 返回 T&、commit() 原子切换 + version++，无 operator\*。RPC 写 JSON 用 `pipeline_g.cache.write() = j`（勿写 `*pipeline_buf_g.write()`——pipeline_buf_g 全局不存在，双缓存是 Pipeline::cache 成员）。装配点写 cache 并发串行用 `std::lock_guard lk(pipeline_g.wr_lock())`。
- **文档已单独存在**：sdk/fins/docs/precedence_graph_design.md 记录调度设计（Running 由 grab 拉取置、Finished 由装配回调回锁置等）。
