# 释放抖动：period jitter 与 absolute jitter

> 状态：已落地。`tool/_csv2jitter.py::analyze_release_jitter` 度量**超周期起始节点**释放时刻的
> 波动，画小提琴图（HTML）+ 打印控制台表。用于回答「定时器释放的精度有多高、误差会不会累积」。

## 1. 测什么

起始节点 = cfg 里**无输入**的节点（`usr_src`），由定时器在每超周期起点释放 —— 建图时 tp 顶点
写入 `job = sleep_until`（**绝对**释放时刻，见 `example/client.cpp` 计时线程段）。它每个超周期
释放一次，理想间隔恒为标称周期 `T`（`cfg` 里该节点的 `period`，ms）。

选它而不是别的节点：下游节点的 `fins:release` 是 **worker 抢到任务的时刻、含排队**，抖动里混着
调度噪声，量级能大一个数量级（实测 CIE 同 run：起始节点 557µs，下游 6820µs）。脚本在显式选了
有输入的节点时会告警。

## 2. 两个口径

设释放时刻序列 `t_0, t_1, …, t_n`，逐拍间隔 `Δ_k = t_{k+1} − t_k`，标称周期 `T`：

| 口径                        | 公式                  | 单位  | 是否累积  |
| ------------------------- | ------------------- | --- | ----- |
| **period jitter**（周期抖动）   | `Δ_k − T`           | µs  | **否** |
| **absolute jitter**（绝对抖动） | `t_k − (t_0 + k·T)` | µs  | **是** |

- **period jitter** = 单拍间隔相对标称的偏差。只反映"这一拍睡得准不准"，与前后拍无关。
  它的标准差 `std周期` 就是通常说的**抖动**（jitter）。
- **absolute jitter** = 该拍实际release时刻相对**理想时刻网格**的偏差。第 k 拍的值 = 前 k 拍
  偏差的累积结果，故它同时含"抖动"与"系统性漂移"两个成分。末拍的值即 `drift`。

控制台另报两个频率口径：

```
std频率 = std(1/Δ)          Hz     频率视角的抖动
ppm     = std周期 / T × 1e6   相对抖动（无量纲，便于跨周期比较）
```

## 4. 怎么读

### 4.1 `drift` 由「均值偏差」决定，不由「抖动」决定

`drift ≈ (mean Δ − T) × (n − 1)`。这是恒等式，实测对到亚 µs：

```
FINS 7B u90 m1:  均值偏差 −3.236 µs/拍 × 1000 拍 = −3236.0 µs   实测 drift = −3235.97 µs
FINS 7B u30 m1:  均值偏差 −1.774 µs/拍 ×  500 拍 =  −886.9 µs   实测 drift =  −886.95 µs
CIE  1MB u90 m2: 均值偏差 +0.002 µs/拍 ×  967 拍 =    +1.5 µs   实测 drift =    +1.45 µs
```

推论：**`std周期` 大不代表 `drift` 大**。CIE 的 `std周期` 是 FINS 的 3.3 倍，但它每拍只系统性偏
0.002 µs，1000 拍下来几乎不漂；FINS 的抖动小，却每拍稳定偏 −3.2 µs，漂移反而大。
关心"跑一小时会不会错拍"看 `drift`，关心"每拍准不准"看 `std周期`。

### 4.2 `std绝对` 不随拍数增长 → 释放点锚在绝对网格上

若每拍偏差相互独立，位置偏差会随机游走，`std绝对` 应随拍数按 `σ√k` 发散。实测不是：

```
FINS 7B u90 m1 n0：std绝对 在 k = 10 / 50 / 200 / 1000 拍时 = 100.5 / 89.5 / 91.3 / 94.2 µs
                    随机游走预期 = σ√k ≈ 159 × √(1000/3) ≈ 2900 µs
```

它稳定在 ~95 µs（≈ `std周期` 量级），且相邻周期的偏差负相关（lag-1 = −0.21）—— 上一拍睡长了，
下一拍就补回来。这正是 `sleep_until`（**绝对**时刻）的行为：每拍重新锚定到理想网格，误差不累积。

对照：若定时器写成 `sleep_for(T)` 的循环（**相对**延时），误差会逐拍累加，`std绝对` 随 √k 发散。
所以这个量能反过来**验证释放是否用了绝对时刻**。

### 4.3 两个口径的分工

| 问题                    | 用哪个             |
| --------------------- | --------------- |
| 定时器每拍准不准？             | `std周期`         |
| 跑一万拍后偏离理想多远？会不会错拍/漏拍？ | `drift`         |
| 偏差相对周期多大？跨周期能否比较？     | `ppm`           |
| 释放是否锚在绝对网格（不累积）？      | `std绝对` 是否随拍数增长 |

## 5. 已知陷阱

| 陷阱              | 表现                                                  | 处理                                             |
| --------------- | --------------------------------------------------- | ---------------------------------------------- |
| 测了**非起始节点**     | 抖动混入调度排队噪声，量级大一个数量级                                 | 脚本对 cfg 里有输入的节点打告警；默认只测起始节点                    |
| 多路径配置各 src 周期不同 | 只锚定第一个 src 在 `H`，其余 src 周期另抽（200 个种子中 173 个出现）      | `periods` **必须逐节点给** `{'n0':100,'n8':50}`，不收标量 |
| `nodes` 传裸字符串   | `'n0'` 被逐字符迭代成 `'n','0'`，静默匹配不到                     | 传入即报错，要求写 `['n0']`                             |
| 窗口只切出很少拍        | 一拍一个样本，`[3000,10000]` 在 T=100ms 下只有 70 拍，violin 不成形 | 给足宽度或留 `None`                                  |
| 间隔 > 1.5T       | 漏释放 / 多等一拍（不是抖动，是事件）                                | 计数上报但**不丢弃**（`n_short`/`n_miss` 列）             |

## 6. 接口

```python
from _csv2jitter import analyze_release_jitter

fig, df = analyze_release_jitter(
    timeline_csv="FINS_serial_7B/multihop_u90_m2_ms01_s20262410_212704_timeline.csv",
    pipeline_json="pipeline_serial/multihop_u90_m2_ms01_s20262410.json",  # 自动取起始节点+周期
    nodes=["n0"],                     # None = cfg 的起始节点（默认，推荐）
    periods={"n0": 100},              # 逐节点覆盖标称周期（ms）；None = 用 cfg 的 period
    analysis_window_ms=None,          # (lo, hi) ms，相对 trace 起点；按该次 release 判定
    clip_pct=99,                      # 只影响图；控制台与 CSV 始终是未裁剪值
    missed_ratio=1.5,
    output_html="release_jitter_violin.html",
    output_csv=None,                  # 逐拍明细
)
fig.show()
```

- 纵轴两个 violin 组：`period jitter` 与 `absolute jitter`（同为 µs，零线用虚线标出）
- `output_csv` 逐拍列：`node / cycle / t_rel_us / interval_us / period_jitter_us / abs_jitter_us / nominal_us`
- 无 `pipeline_json` 时无法识别起始节点，退化为测**全部**有 release 的节点，标称周期用实测间隔
  中位数（表格 `来源` 列显示 `median` 而非 `cfg`）
